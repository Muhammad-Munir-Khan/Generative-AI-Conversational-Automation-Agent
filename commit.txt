AGENT RECURSION-LOOP FIX:
The agent hit recursion limit on compound questions because document_search
and knowledge_base_search had overlapping behavior after the prior KB
integration switched rag_answer to retrieve_merged. The agent oscillated
between the two tools, retrying with reworded queries until it ran out of
iterations.

- chain.py: split into rag_answer (merged, used by /rag/query) and
  rag_answer_personal_only (personal-only, used by document_search tool)
- document_search.py: calls rag_answer_personal_only -- restores its
  documented "personal docs only" scope, eliminates the overlap
- graph.py SYSTEM_PROMPT: explicit anti-thrash rules - "call each retrieval
  tool at most once per turn", "for compound questions formulate ONE broad
  query, do NOT issue one search per sub-question"
- config.py: max_agent_iterations 6 -> 8 (recursion limit 16 -> 20) as a
  safety net

GLOBAL FORCE-LOGOUT (security):
Force-logout was previously enforced only on /admin/* endpoints because
current_active_user (used by chat/RAG/sessions) didn't check
jwt_invalidated_at. Force-logging-out a regular user did nothing visible.

- auth.py: current_active_user now wraps the fastapi-users dependency with
  the iat-freshness check. Every authenticated endpoint - chat, RAG,
  sessions, admin - rejects tokens issued before jwt_invalidated_at.
- current_active_fresh_user kept as alias for backward compat with
  admin_deps.py.
- Verified: chat endpoints return 401 immediately on victim's next request
  after force-logout. Frontend's apiFetch catches the 401 and redirects to
  /login. User re-authenticates to get a fresh token.
